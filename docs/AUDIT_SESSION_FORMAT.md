# DGraInsight Audit Session Format

Status: legacy Audit Session v1 compatibility format. Its empirical p and case-level BH fields are not Pipeline v2 formal evidence. The CLI defaults to Session v2; see `AUDIT_SESSION_V2.md`.

Canonical schema: `schemas/dgrainsight_audit_session_v1.schema.json`

Schema version: `dgrainsight.audit_session.v1`

## Generating a session from a local checkpoint and dataset

The normal user workflow is:

```powershell
python -m dgraudit validate --config configs/local_audit_dgraformer_etth1.json
python -m dgraudit audit --config configs/local_audit_dgraformer_etth1.json --output dgrainsight_session.json
```

Replace the config with `configs/local_audit_msgnet_etth1.json` for MSGNet. The `audit` command repeats the required preflight, runs real baseline, graph extraction, exact intervention and matched-control checkpoint replays locally, computes statistics, and writes one JSON document. It does not use the built-in demo catalogs. The resulting file is the file selected in the website's **Import Audit Session** control.

Use `configs/local_audit_mtgnn_exchange.json` for MTGNN. Run `python -m dgraudit edges --config <config>` first to display the native graph count, context IDs, retained-edge counts, and ranked real edge candidates before editing the exact relation.

The browser never receives the checkpoint or dataset and never executes inference. Local filesystem paths are omitted from the portable session; hashes, runtime versions, the preflight summary, exact selections, outputs, controls, statistics, and provenance are retained.

## Round-trip exporting of built-in artifacts

The artifact exporter accepts only the two explicit official demo mappings. It is retained for regression tests of historical immutable evidence and is separate from the user-facing direct local audit:

```powershell
python -m dgraudit.cli.export_audit_session --config configs/export_session_dgraformer_etth1.json
python -m dgraudit.cli.export_audit_session --config configs/export_session_msgnet_etth1.json
```

Each command writes one `dgrainsight_session.json` under `artifacts/sessions/<model>_etth1/`. Use `--output <path>` to select a different destination. The writer first builds the complete document, verifies source hashes and semantic references, and only then atomically replaces the destination. A failed export does not leave a partial session.

These configurations round-trip existing immutable catalogs, so their provenance uses `artifact_roundtrip_validation`. Sessions created by `python -m dgraudit audit` carry `adapter_preflight` provenance and the newly replayed outputs.

## 1. Purpose

A DGraInsight Audit Session is one portable JSON document generated by the validated offline audit pipeline. It contains stored model-native graphs, exact relation selections, checkpoint-replayed outputs, matched controls, statistics, missing/availability states, and provenance needed by the browser exploration workflow.

An Audit Session is not an arbitrary JSON upload and does not contain an executable model. Importing it never runs neural inference, extracts a graph, applies an intervention, or recomputes a scientific statistic.

Audit Session v1 officially represents:

- DGraFormer with native window graph contexts.
- MSGNet with native layer/scale graph contexts.
- MTGNN with one native global learned graph shared across its GCN layers.

Additional architectures require a model-specific offline adapter. Audit Session v1 is self-describing: if the adapter exports its real native context through the common graph/evidence contract, the existing website can validate and display that new model without adding a frontend model enum or redeploying model-specific UI code. A new schema version is needed only when the architecture has semantics that v1 cannot preserve losslessly.

## 2. Top-level structure

```text
schema_version
session
model
dataset
checkpoint
audit_plan
samples[]
relations[]
evidence_records[]
evidence_summary
cross_run_evidence
provenance
limitations[]
model_specific (optional)
```

The common structure separates reusable scientific objects:

- A sample stores history, truth, baseline prediction, and native graph contexts once.
- A relation stores source/target identity and native graph occurrences once.
- Evidence records reference the sample baseline instead of duplicating it for every intervention.
- Local and broader-context evidence have distinct exact selections.

This normalization is lossless but avoids repeating a `96 × 7` baseline and the same graph matrices hundreds of times.

## 3. Tensor representation and axis order

Every stored tensor declares:

```json
{
  "dtype": "float32",
  "shape": [96, 7],
  "axis_order": ["forecast_step", "variable"],
  "values": [],
  "sha256": "optional canonical tensor hash"
}
```

The number of axis labels must equal the number of shape dimensions, and nested values must match the declared shape. These conditions require semantic validation in addition to JSON Schema validation.

Canonical v1 axes are:

| Data | Axis order |
|---|---|
| History, when available | `input_step, variable` |
| Ground truth | `forecast_step, variable` |
| Baseline prediction | `forecast_step, variable` |
| Intervention prediction | `forecast_step, variable` |
| Graph matrices | `source_node, target_node` |
| Per-step response | `forecast_step` |
| Per-variable response | `variable` |

Current web artifacts do not all use the same orientation:

- DGraFormer sample JSON uses `[variable][step]` for history, truth, and prediction.
- DGraFormer intervention catalogs use `[step][variable]`.
- MSGNet catalog uses `[variable][step]` for sample and global intervention trajectories.

The exporter must transpose only when required by the declared source orientation. Round-trip tests compare canonicalized tensors and their declared axes, not raw source nesting without its source-axis interpretation.

No rounding, normalization, inverse normalization, or scientific value transformation is performed during this conversion.

History uses the same available/missing wrapper as other optional tensors. A newly executed supported audit has the real adapter input and stores it as available. Older DGraFormer 40-grid evidence artifacts do not retain history for every audited test index; those sessions use `status: missing, value: null` with an explicit reason. The exporter must not borrow history from another sample.

## 4. Exact selection identity

Every evidence record has one complete exact selection:

```text
model
dataset
sample_id
sample_index
context_type
context_id
context_index
layer (MSGNet when applicable)
source
target
source_name
target_name
scope
```

Local DGraFormer example:

```json
{
  "model": "DGraFormer",
  "dataset": "ETTh1",
  "sample_id": "test:0",
  "sample_index": 0,
  "context_type": "window",
  "context_id": "window:0",
  "context_index": 0,
  "source": 0,
  "target": 4,
  "source_name": "HUFL",
  "target_name": "LUFL",
  "scope": "local"
}
```

Local MSGNet example uses `context_type: scale`, a `layer`, and a scale index. Broader evidence uses `window_set/all_applicable` or `scale_set/all_applicable`; it does not pretend to be one local window or scale.

The importer must construct a unique key from every field above. If the key is not present, it displays:

```text
No evidence available for this exact selection.
```

It must not substitute another sample, relation, window, scale, layer, or scope.

## 5. Evidence status and null semantics

Evidence records use four statuses:

| Status | `value` | Meaning |
|---|---|---|
| `available` | Evidence payload | Exact intervention ran and is scientifically interpretable within its stated limitations. |
| `not_exposed` | Evidence payload | Replay exists, but the selected DGraFormer window was not in the sample computation path. Stored zero/identity-like results remain preserved and must not be interpreted as functional support. |
| `missing` | `null` | The scientific result was not computed or does not exist. |
| `unavailable` | `null` | The requested result cannot be supplied by this session. |

For genuine missing evidence, the required representation is:

```json
{
  "status": "missing",
  "value": null,
  "reason": "Only one real ETTh1 checkpoint is available."
}
```

The exporter must never convert missing values to zero.

DGraFormer `window_active=false` is distinct from missing. The current catalog contains actual replay records with zero prediction change, p-values of 1, and explicit undefined-effect metadata. Those values remain in a `not_exposed` payload so the round trip is lossless, while the status prevents them from being presented as exposed evidence.

Individual unavailable metrics remain `null` and retain an explicit `metric_status`, for example an undefined standardized effect when control variance is zero.

## 6. Negative evidence

Negative evidence is a completed result, not a failure or a missing value. An evidence record remains `available` when:

- prediction change is zero or very small;
- error improves rather than worsens;
- empirical p-value is not significant;
- BH-adjusted p-value is at least 0.05;
- graph weight and intervention response disagree.

All evidence records in the declared audit family are exported. No supported-only filter is allowed.

The session stores offline-generated summary counts so the imported UI does not have to recompute them. Current MSGNet ETTh1 regression invariants are:

```text
local_case_count = 630
broader_context_case_count = 210
local_bh_supported_count = 0
broader_context_bh_supported_count = 0
negative_evidence_preserved = true
```

## 7. DGraFormer mapping

### 7.1 Source artifacts

| Session section | Current source |
|---|---|
| Model/dataset | Audit config, adapter metadata, ETTh1 catalogs |
| Checkpoint/data hashes | Phase 5 and global run manifests; sample provenance |
| Sample history/truth/baseline | Offline adapter batch/output; built-in sample JSON when round-tripping existing demo cases |
| Window contexts | Adapter `extract_graph_stages().windows`; raw `graphs/window_*.json`; built-in sample `windows[]` |
| Relations | Local catalog `edges[]` and case edge objects |
| Local evidence | legacy fixture `legacy/v1/artifacts/public-data/evidence/etth1_intervention_catalog.json` cases |
| Broader evidence | legacy fixture `legacy/v1/artifacts/public-data/evidence/etth1_global_intervention_catalog.json` cases |
| Local controls | Phase 5 `controls/s*_w*_e*_*.json` records plus case summaries |
| Broader controls | Global run `controls/s*_e*_*.json` records plus case summaries |
| Provenance | source run IDs, manifests, raw operand paths and hashes |
| Cross-run | Existing `status: missing`, `metrics: null`, reason |

### 7.2 Window context mapping

Each native DGraFormer window becomes one `graphContext`:

```text
context_id                 <- "window:" + window
type                       <- "window"
index                      <- window
graphs.static_prior        <- static_prior
graphs.raw_score           <- raw_score
graphs.activated           <- activated
graphs.diagonal_removed    <- diagonal_removed
graphs.topk_mask           <- topk_mask
graphs.topk_graph          <- topk_graph
graphs.self_loop_graph     <- self_loop_graph
graphs.normalized          <- normalized
native_metadata.topk_slots <- topk_slots
native_metadata.blend_proportion <- blend_proportion
```

Built-in sample fields such as start/end, active input steps, and the existing web display matrices remain under `native_metadata` or `model_specific` when present. They do not replace the model-native extraction stages.

### 7.3 Local evidence mapping

```text
evidence_id              <- conclusion_id
status                   <- window_active ? available : not_exposed
selection.sample_index   <- sample_index
selection.context_index  <- window
selection.source/target  <- edge.source/edge.target
metrics                  <- structural_metrics excluding control/statistical fields promoted below
statistics               <- empirical p, BH p, percentile, effect size, CI, weight-impact statistics
metric_status            <- structural_metric_status
intervention_output      <- intervention_prediction
baseline_output_ref      <- canonical sample baseline ID
controls.count           <- controls.repetitions
controls.random_seed     <- controls.random_seed
controls.records         <- hydrated controls record file
diagnostic_localization  <- diagnostic_localization, step impact, step error delta, variable impact
provenance               <- raw_operands and source run references
```

Channel-mask metrics are preserved under `model_specific.channel_mask_metrics`; they are not silently merged with structural-edge evidence.

### 7.4 Broader-context mapping

```text
context_type             <- window_set
context_index            <- all_applicable
scope                    <- broader_context
graph_effect.retained_contexts <- retained_windows
graph_effect.exposed_contexts  <- exposed_windows
graph_effect.affected_contexts <- affected_exposed_windows
metrics/statistics       <- case.metrics
intervention_output      <- intervention_prediction
controls.records         <- hydrated controls_file
```

DGraFormer cross-run remains exactly missing/null because only one real ETTh1 checkpoint exists.

## 8. MSGNet mapping

### 8.1 Source artifacts

| Session section | Current source |
|---|---|
| Model/dataset/checkpoint | MSGNet ETTh1 catalog and audit config |
| Samples | `samples[]` history, truth, prediction, metrics |
| Scale contexts | `samples[].contexts[]` |
| Local relations/evidence | `samples[].edge_impacts[]` |
| Broader evidence | `samples[].global_edge_impacts[]` |
| Run provenance | baseline, graph, evidence and global run IDs |

### 8.2 Scale context mapping

Each native scale becomes one `graphContext`:

```text
context_id                         <- "layer:" + layer + ":scale:" + scale_index
type                               <- "scale"
layer                              <- layer
index                              <- scale_index
graphs.adaptive                    <- adaptive
graphs.effective                   <- effective
native_metadata.period             <- period
native_metadata.fft_strength       <- fft_strength
native_metadata.scale_contribution <- scale_contribution
```

When a newly generated offline audit has raw affinity, activated, or self-loop stages, those are stored as additional named graph tensors. Their absence from an older web catalog is not filled synthetically.

### 8.3 Local evidence mapping

```text
evidence_id              <- conclusion_id
status                   <- available
selection.layer          <- layer
selection.context_index  <- scale_index
selection.source/target  <- source/target
graph_effect.weight      <- adaptive_weight
metrics                  <- prediction and error delta fields
statistics               <- statistics
controls.values          <- controls.prediction_delta_abs
controls.count/protocol  <- controls.count/sampling
limitations              <- limitations
```

The current MSGNet web catalog does not contain local intervention prediction trajectories. For a round trip of that catalog:

```json
{
  "status": "missing",
  "value": null,
  "reason": "The source MSGNet local evidence catalog stores response metrics but not the intervention prediction trajectory."
}
```

A newly executed supported local audit must store the actual replay trajectory instead.

### 8.4 Broader-context mapping

```text
context_type                  <- scale_set
context_index                 <- all_applicable
scope                         <- broader_context
graph_effect.affected_contexts <- affected_scales
graph_effect.scale_weights    <- scale_weights
metrics/statistics            <- global edge impact fields
intervention_output           <- intervention_prediction
controls.count/protocol       <- controls.count/sampling
controls.values               <- the other 41 stored same-sample global edge impacts, selected in source-target order
```

The current global catalog does not repeat the raw control array inside each case, but its declared protocol defines controls as all other 41 directed non-self global edge impacts in the same sample, and every one of those impacts is stored in the same case family. The offline exporter therefore materializes `controls.values` by selecting those 41 stored values in deterministic source-target order. This is lossless record selection, not statistical recomputation. The imported browser consumes the stored array and does not reconstruct it.

MSGNet cross-checkpoint evidence is represented as not evaluated/missing because the catalog contains only one checkpoint lineage and makes no cross-checkpoint claim.

## 9. Provenance

Required portable provenance includes:

- session generation run ID;
- validation kind, status, and report SHA-256;
- audit config SHA-256;
- dataset and checkpoint SHA-256;
- adapter, model, dataset and runtime metadata;
- source run IDs and their artifact availability;
- commands and code references;
- source artifact paths and hashes when available.

Absolute local paths are provenance hints, not portable locators and may be `null`. Hashes and stable run IDs carry identity.

Some MSGNet catalog run IDs currently reference run directories not present in this repository. They remain recorded with:

```text
artifact_status = referenced_not_present
manifest_sha256 = null
```

The exporter must not claim those manifests were verified.

New supported audits use `validation.kind: adapter_preflight`. A round-trip export of immutable legacy built-in catalogs uses `validation.kind: artifact_roundtrip_validation` and hashes a report that validates source artifact structure, hashes, references, and catalog invariants. That legacy validation does not claim the current local checkpoint/dataset inputs passed the new adapter preflight.

## 10. Semantic validation invariants

JSON Schema validation is necessary but not sufficient. `validateAuditSession()` and the Python exporter validator must also enforce:

1. IDs are unique within samples, relations, contexts, and evidence records.
2. Every relation sample reference resolves to exactly one sample.
3. Every evidence relation reference resolves to exactly one relation.
4. Model, dataset, sample, source, target, names, and native context agree across all references.
5. Source and target are distinct and within the dataset variable range.
6. Local context IDs resolve to an existing native context of the same type.
7. DGraFormer sessions contain only window native contexts; MSGNet sessions contain only scale native contexts; MTGNN sessions contain only a global graph context.
8. Broader selections use `window_set` or `scale_set` and `all_applicable`; MTGNN does not declare a synthetic broader context.
9. Tensor shape, axis count, nested values, finiteness, and optional hash agree exactly; a missing history tensor remains null.
10. `missing` and `unavailable` evidence always has `value: null` and a reason.
11. `available` and `not_exposed` evidence has a payload.
12. A missing intervention trajectory never becomes a zero tensor.
13. Stored p-values, BH-adjusted p-values, effect sizes, confidence intervals, and control summaries are never recomputed on import.
14. Summary counts agree with the exported record family; the browser displays the stored summary.
15. No evidence key is silently repaired or replaced.

## 11. Round-trip equality contract

DGraFormer round-trip compares:

- real sample index and optional display ID;
- every window ID and native graph-stage tensor;
- source, target, names, weights, ranks and retained contexts;
- baseline, intervention and truth tensors after source-axis canonicalization;
- prediction/error delta fields;
- complete hydrated control records and hashes;
- statistics, metric-status reasons and diagnostic localization;
- source run IDs and provenance hashes;
- `not_exposed` cases and their stored values;
- cross-run `missing/null` state.

MSGNet round-trip compares:

- sample index;
- layer, scale index, period, FFT strength and scale contribution;
- adaptive/effective graph tensors;
- source, target, names and adaptive weight;
- baseline/truth and available intervention tensors;
- all local and broader response metrics;
- local raw control values and all stored control summaries;
- local/global BH-supported counts remaining `0`;
- local trajectory remains missing/null, while broader-context controls remain the 41 deterministically selected stored values;
- source run IDs and their availability status;
- the 41 broader-context control values selected from the stored same-sample global case family, with their stored summaries unchanged.

Floating-point values use serialization-safe equality: parsing and writing JSON must reproduce the same finite IEEE value. No display rounding is used for equality tests.

## 12. Import behavior

The browser import sequence is implemented strictly as:

```text
parse JSON
→ validate schema version
→ validate JSON Schema structure
→ validate semantic references and tensor shapes
→ atomically install imported session state
→ display stored values
```

Failure leaves the built-in demo untouched and reports a concrete reason under:

```text
Invalid or incompatible DGraInsight Audit Session
```

Top-K, threshold, and ratio controls may filter visible graph edges only. They must not alter stored contexts, relation identity, evidence, controls, statistics, or provenance.

The import UI is exposed under **Built-in Demo or Portable Audit Session**. It accepts one local `.json` file, validates it entirely in memory, and installs it atomically only after every check succeeds. The active imported session records its model, dataset, adapter, checkpoint hash, generation run, and source filename. **Close Imported Session** / **Return to Built-in Demo** removes imported state and restores the model that was active before import.

The implementation is split between:

- `src/data/auditSession.ts`: v1 types, JSON parsing, structural validation, semantic reference validation, tensor checks, and exact evidence lookup.
- `src/store/useAuditSessionStore.ts`: atomic imported/built-in source state and non-destructive failure handling.
- `src/components/AuditSessionImport.tsx`: file selection, validation progress, source identity, explicit errors, and return-to-demo control.
- `src/components/ImportedAuditWorkspace.tsx`: read-only native graph exploration and stored evidence presentation.

Imported DGraFormer sessions retain window contexts. Imported MSGNet sessions retain layer/scale contexts, period, FFT strength, and scale contribution. Imported MTGNN sessions retain the learned global adjacency and its transpose metadata. An evidence lookup uses the complete exact selection and returns no result when any sample, context, source, target, or scope field differs. The browser never requests a nearest stored case.

The imported evidence workspace displays stored metrics, statistics, matched-control values, intervention-output availability, limitations, and provenance. It does not recompute p-values, confidence intervals, effect sizes, graph matrices, or model outputs. For an available trajectory it displays the first stored values directly; for a genuinely absent trajectory it displays the stored missing/null reason.
