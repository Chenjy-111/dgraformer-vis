# DGraInsight Supported Local Audit

Status: supported-input contract for Audit Config v1 and Audit Session v1, with both official real-input preflights passed on 2026-08-30.

## 1. What is supported

DGraInsight Local Audit v1 has two official model-specific integrations:

| Adapter ID | Model | Native graph context | Supported data profile |
| --- | --- | --- | --- |
| `dgraformer` | DGraFormer | window | ETTh1 hourly CSV (`ett_hour`) |
| `msgnet` | MSGNet | layer + scale | ETTh1 hourly CSV (`ett_hour`) |

This is not arbitrary-model support. A checkpoint, dataset, or architecture outside these contracts must fail preflight or be integrated through a new adapter. DGraInsight does not guess model internals, dataset preprocessing, graph locations, or intervention points.

The browser never runs PyTorch or neural inference. Checkpoint loading, graph extraction, identity replay, exact intervention replay, controls, and statistics belong to the offline pipeline. The browser validates and displays a portable session generated by that pipeline.

## 2. Runtime prerequisites

Local validation requires:

- a Python environment compatible with the selected upstream model and PyTorch;
- the original model source tree;
- an ETTh1 CSV with the exact ordered columns below;
- a raw PyTorch `state_dict` checkpoint compatible with the declared model configuration;
- a DGraInsight Audit Config v1 JSON document.

Required ETTh1 column order:

```text
date,HUFL,HULL,MUFL,MULL,LUFL,LULL,OT
```

The validator does not rename or reorder columns, infer the target, fill missing data, or unwrap an unknown checkpoint structure.

Official source-tree checks:

- DGraFormer: `exp/exp_main.py` and `models/DGraFormer.py`.
- MSGNet: `models/MSGNet.py` and `data_provider/data_loader.py`.

## 3. Configure an audit

Start from the model-specific examples:

- `configs/local_audit_dgraformer_etth1.json`
- `configs/local_audit_msgnet_etth1.json`

Change only paths and values that describe the real checkpoint, dataset, requested samples, exact relations, and the checkpoint's real model configuration. Relative paths are resolved from the config file.

The exact selection fields are:

```text
sample + native context + source + target
```

DGraFormer requires a window context:

```json
{"type": "window", "index": 0}
```

MSGNet requires a layer/scale context:

```json
{"type": "scale", "layer": 0, "index": 2}
```

The validator never substitutes a different sample, window, scale, source, or target when the requested relation is unavailable.

## 4. Run preflight

Use the local command-line program:

```powershell
python -m dgraudit validate --config configs/local_audit_dgraformer_etth1.json
```

To retain the machine-readable report:

```powershell
python -m dgraudit validate `
  --config configs/local_audit_dgraformer_etth1.json `
  --output artifacts/preflight/dgraformer_validation.json
```

The same commands apply to the MSGNet config.

Exit codes:

- `0`: all nine checks passed; `READY FOR AUDIT`.
- `2`: an expected, explained incompatibility; `NOT READY`.
- `1`: an internal CLI/validator defect.

The ordered gate validates config and adapter registration, input paths and hashes, dataset schema, every requested sample, checkpoint loading, a real baseline forward pass, native graph extraction, identity/no-change replay, and exact intervention availability. After the first failure, all dependent checks are marked `not_run`; validation never reports partial success as audit-ready.

The complete contract and failure codes are documented in `docs/PREFLIGHT_VALIDATION_DESIGN.md`.

## 5. Run the local audit and generate the JSON

After editing one of the model-specific Audit Config v1 examples, run:

```powershell
python -m dgraudit audit `
  --config configs/local_audit_dgraformer_etth1.json `
  --output dgrainsight_session.json
```

For MSGNet:

```powershell
python -m dgraudit audit `
  --config configs/local_audit_msgnet_etth1.json `
  --output dgrainsight_session.json
```

`audit` always reruns V01-V09 before doing scientific work. It then loads the declared real checkpoint and dataset, computes each requested sample baseline and native graph, replays every exact requested intervention, executes real eligible edge interventions for the model-specific control family, computes the stored statistics and Benjamini-Hochberg adjustment, and atomically writes one portable JSON file. DGraFormer uses retained same-window controls locally and retained-context-count/mean-weight matching for broader context; MSGNet uses all other directed non-self edge removals in the same sample and scope. It does not read the built-in web evidence catalogs.

The default is 2,000 bootstrap repetitions. Use `--bootstrap <count>` to change that declared statistical setting. A failed preflight or replay produces no partial output and does not substitute another sample, context, or relation.

The older `python -m dgraudit.cli.export_audit_session` command remains only for regression-testing the round trip of the project's existing immutable demo artifacts. It is not the command users run on their own checkpoint and data.

## 6. Import in the web interface

1. Build or start the DGraInsight web app.
2. Under **Built-in Demo or Portable Audit Session**, choose **Import Audit Session**.
3. Select a DGraInsight Audit Session v1 JSON file.
4. Confirm the displayed model, dataset, adapter, checkpoint hash, and generation run.
5. Select an evidence-bearing relation and use **Test this exact relation**.
6. Use **Close Imported Session** or **Return to Built-in Demo** to restore the prior demo model.

Invalid JSON, unsupported versions, broken references, inconsistent relations, invalid tensor shapes, and invalid missing/null values are rejected explicitly. A failed import leaves the active built-in or imported source unchanged.

Top-K, threshold, and ratio controls filter visible edges only. They do not change stored graphs, evidence identity, interventions, controls, statistics, or provenance.

See `docs/AUDIT_SESSION_FORMAT.md` for the complete schema, missing/null rules, negative-evidence rules, provenance, and round-trip equality contract.

## 8. Scientific failure policy

The correct outcome is:

```text
supported, compatible input -> reliable success
unsupported or invalid input -> explicit failure
stored unavailable evidence -> unavailable
stored missing evidence -> missing + null
statistically unsupported response -> preserved negative evidence
```

DGraInsight must never use mock values, zero filling, heuristic graph discovery, nearest-case substitution, or silent repair to make an audit appear successful.
